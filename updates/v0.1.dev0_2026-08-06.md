# v0.1.dev0 (2026-08-06)

LiteLLM 统一模型封装（26 厂商）+ 模型提供商管理页面 + LLM 对话页面（@ant-design/x 流式思考）+ 机器人本体更新方案 + i18n 体系重构 + 面板表单统一 + OneBot/snowluma 接入修复。

## LiteLLM 统一模型封装（核心重构）

**背景**：自研的 openai/anthropic/ollama 三个平台适配器全部废弃（~430 行），改为单文件 `loyan/brain/provider/types/litellm.py`（553 行）经 litellm 单接口调用 100+ 平台。

**封装能力**（单文件完整包含）：
- `chat` / `chat_stream`（流式）/ `embedding` / `list_models`，对齐 BaseProvider 协议（`{content, model, usage, time}` 与 `{type:text/done}`）
- 消息多模态转换（URL/data:image/本地文件 → image_url 段）
- 流式 thinking 剥离（ThinkStrip 状态机）+ 工具调用组装（ToolCallBuffer）
- usage/token 归一化；错误映射（litellm 异常 → provider/errors 体系）
- 模型能力探测：唯一来源 = `litellm.get_model_info`（零硬编码模型名，未知模型保守默认）
- **多 key 轮换**：api_key 逗号分隔，最左优先，失败自动右移（chat/chat_stream 均实现）
- **strip_think 请求级覆盖**：`strip_think=False` 时思考内容以 `reasoning` 事件透传（R1 类模型）
- `_full_model` 修复：openai_like 前缀**无条件**加 `openai/`（模型名自带斜杠的厂商，如硅基流动 `deepseek-ai/xxx`，此前前缀永远加不上导致对话失败）
- `models` 填充修复：实例默认模型 + custom_models → `prov.models`（此前类属性空列表，engine 取 models[0] 恒空 → "未指定模型"）

**26 个厂商清单**（VENDORS，含 icon/category）：
- 原生计费 19 个：OpenAI/Anthropic/Ollama/Gemini/DeepSeek/智谱(zai)/百炼(dashscope)/豆包(volcengine)/Kimi/MiniMax/混元(tencent)/Mistral/Groq/Together/OpenRouter/Perplexity/xAI/Azure/Bedrock/LM Studio
- 原生调用但价格未收录 2 个：小米 MiMo（`xiaomi_mimo` 前缀）、硅基流动——需 custom_pricing
- openai_like 兼容通道 5 个：百川/零一/百度/讯飞（文档确认无官方支持）
- 前缀修正记录：doubao→volcengine、hunyuan→tencent、zhipu→zai（文档核实，此前误归 openai_like）、xiaomi→xiaomi_mimo
- **26 端点全部验证**：直连 17 + 代理 6（OpenAI/Anthropic/Gemini/Mistral/Perplexity/xAI 走 socks5:3067）+ 本地 2（Ollama/LM Studio 未启动服务）+ 跳过 1（Bedrock 环境变量）

**自定义计费（register_model）**：litellm 官方机制，`custom_pricing` 按"元/百万 token"填写（与厂商官网一致）→ 注册时 ÷汇率÷1e6 转美元/token → `completion_cost` 可算。`cost.py` 统一人民币记账（`EXCHANGE_RATE=7.2`），面板显示固定两位小数（`0.00` 格式，不再科学计数）。

## LLM 对话页面（@ant-design/x）

- 菜单"LLM对话"（sidebar 词条）+ `/chat` 路由；页面独立于任何适配器（面板直连 brain）
- 布局：左侧会话列表（Conversations：新建/切换/删除，消息持久化 `chat_sessions.db`）+ 右侧聊天主区（Welcome+Prompts 空态 / Bubble.List 气泡流 autoScroll）
- **SSE 流式**：`POST /api/loyanui/chat/stream`（Quart stream_with_context）→ 前端 getReader 解析 `data:` 事件（text 增量/reasoning 增量/done）

- 思考透传修复：litellm 对 R1 的思考在 `delta.reasoning_content`（非 content 标签）——已透传

## 机器人本体更新方案

- `loyan/core/update_manager.py`（UpdateManager，与 config_manager 同位置同命名风格）：
  - 检查更新（GitHub Releases API，对比 `loyan.__version__`）/ 下载 / **SHA256 强校验（损坏/篡改拒绝执行）** / 备份项目根（排除 storage/.venv 等）/ **解压覆盖整个源码目录（storage 永不触碰，包内含 storage 拒绝）** / 回滚（备份恢复，保留 3 份）/ pip 形态分支（提示 pip install -U）
  - 解压路径安全（拒绝绝对路径/.. 穿越）
- CLI：`loyan update check/apply/rollback`（打印 changelog，apply 后确认重启）
- 面板：`UpdateChecker.jsx`（主题按钮旁：**图标按钮无文字**；检测到新版本 → 图标左侧显示"发现新版本 vX"；点按钮 → Modal 显示 changelog + 确认更新；**无更新时只有关闭按钮**）；`/update/check|apply|changelog` 路由
- 后台定时检查：启动 30s 后 + 每 `update_check_interval_hours`（默认 24h），配置 `auto_update_core`（默认 false，只检查提示不自动装）
- schema 新增 `update_check_interval_hours` / `auto_update_core`
- 发布：`.github/workflows/build-update.yml`（tag 触发打包 `loyan-update-{ver}.tar.gz` + sha256 + updates/ 日志作 Release body）
