# v0.1.dev0 (2026-08-03)

指令前缀 canonical 归一化扩展到插件命令 + 插件安装链路三个隐藏 bug + CLI 插件命令 pip 全局适配 + 插件商店配置迁移到 config.json + 404 页面。

## 指令前缀：canonical 归一化扩展到插件命令（核心修复）

**问题**：把命令前缀从 `/` 改为 `#`（互斥模式）后，部分插件指令匹配失败。`#跑图 晨曦王国` 被识别为命令但回复"未知地区：#跑图"，参数提取完全错乱。

**根因**：插件参数提取依赖 `ctx.raw_text.replace(ctx.command, "", 1)`——隐含假设"注册名一定出现在消息文本中"。`ctx.command` 是注册名 `/跑图`，但用户消息是 `#跑图`（新前缀形态），replace 找不到 `/跑图` 子串，整个消息变成参数。内置命令早有 canonical 归一化（`!关于` → `/关于`），插件命令缺这层处理。

**修复**（`loyan/core/pipeline/command_matcher.py`）：
- `_match_any` 返回值从"原命令"扩展为 `(原命令, 实际命中形态)` 元组
- 新增 `_normalize_command`：命中形态 != 注册名时，把 `ctx.raw_text` 中的命中形态替换为注册名（`#跑图 晨曦王国` → `/跑图 晨曦王国`）
- 路径 A（TOML 命令）与路径 B（@on_command 装饰器）匹配成功处统一调用
- 语义保证：匹配后 `ctx.command` 一定出现在 `ctx.raw_text` 中——插件 `raw_text.replace(ctx.command)` 参数提取永远成立
- 连带收益：命令别名命中（`zz` → `/跑图`）同样归一化，别名场景不再踩同类坑

**验证**：修复前 `#跑图 晨曦王国` → "未知地区：#跑图"；修复后 → "晨曦王国探索进度：4/22"。老插件零改动。

**AstrBot 调研结论**（对比参考）：AstrBot 走"注册名不带前缀 + 唤醒层剥前缀 + 参数按注解注入 parsed_params"路线，插件从不接触原始消息；我们保留自己的插件风格（注册名带 `/` + 插件自己抠参数），用归一化保证兼容——不照搬对方架构。

## 插件安装链路：三个隐藏 bug（面板商店安装/更新必现）

**背景**：新插件（loyan-sticker/loyan-game）通过面板商店安装后，前端提示框报 `PluginStore._reload_plugin() takes 1 positional argument but 2 were given`。安装文件成功但热重载报错，且事件通知发不出去。

**Bug 1：`_reload_plugin` 漏 `self` 参数**
- `plugin_store.py` 中 `def _reload_plugin(plugin_id: str)` 定义在类体内但无 self，被 `self._reload_plugin` 访问时绑定成方法 → 调用传 2 参 → TypeError
- 修复：加 `@staticmethod`（调用处不变）
- 引入时间：08:18（最后一次成功安装）之后、10:23 之前的重构——git 中该文件从未被跟踪，无法回溯具体提交

**Bug 2：`_enable_if_disabled` staticmethod 与 self 矛盾**
- `@staticmethod def _enable_if_disabled(self, plugin_id)`——staticmethod 不绑定 self，调用传 1 参但签名要 2 参 → TypeError
- 修复：删 `@staticmethod`（变实例方法）
- 该 bug 被 Bug 1 掩盖（Bug 1 先抛异常，此函数未执行），修复 Bug 1 后必须同步修

**Bug 3：`_plugin_manager` 函数未定义**
- `_enable_if_disabled` 内调用 `_plugin_manager()`，全文件无此定义 → NameError 被 except 吞掉，安装后"重装自动解除禁用"功能静默失效
- 修复：改用模块级 `plugin_manager`（顶部已 import）

**Bug 4：`_emit_async` 在线程池中 create_task 失败**
- 安装/更新走 `asyncio.to_thread(self._reload_plugin)` → reload_plugin 内 `_emit_async` 调 `asyncio.create_task`，线程池线程无 running loop → `no running event loop` + `coroutine never awaited` 警告
- 修复（`plugin_manager.py`）：`_emit_async` 优先取 running loop，无则投递主循环（`run_coroutine_threadsafe`，`_main_loop` 在 `async_load` 中保存），主循环不可用则静默跳过（debug 日志）
- 影响面：此前面板装任何插件都会打此错误，事件通知（PLUGIN_LOADED 等）发不出去

**回归测试**（`unit/plugin/test_plugin_store_install.py`）：reload/enable 调用不再抛参数错误、无 loop 线程调 `_emit_async` 不抛错、`store_install` skip_reload 参数行为。

## CLI 插件命令：pip 全局安装适配

**背景**：CLI 是旧逻辑（强制 bot.py 本地项目），全局 pip 安装用户无法用 `loyan plugin` 系列命令；安装目标写死系统插件目录（pip 升级覆盖）；不支持商店安装通道。

**改动**：
- `cli/utils.py`：`find_plugins_dir` 改指向 `storage/plugins`（用户目录，与商店一致，pip 升级不覆盖）；新增 `system_plugins_dir`
- `cli/plugins.py`（重写）：
  - `list_plugins`：扫描系统 + 用户双目录，标注来源（[系统]/[用户]）
  - `install_plugin`：四路分流——纯目录名（重装依赖）/ 本地路径（复制）/ GitHub 简写 `user/repo`（**商店通道优先**：codeload zip + 镜像链 + 安全校验，失败回退 git clone）/ git URL
  - `update_plugin`（新增）：复用 `store_update`（备份 + 失败回滚）；非商店插件提示 git pull
  - `remove_plugin`：只删用户插件，系统内置拒绝（升级会还原）
- `cli/app.py`：plugin list/install/remove 去掉 `_ensure_local_root`（bot.py）强制，pip 全局可用；新增 `plugin update` 命令；disable/enable 提示"运行中需重启或到面板"
- `plugin_store.py`：`store_install`/`store_update` 新增 `skip_reload` 参数——CLI 进程外安装跳过运行时 reload（机器人运行中由 watchfiles 热重载接管），回滚路径同步处理
- **顺带修复**：install 的 existing 分支对绝对路径 source 失效（`plugins_dir / 绝对路径` 覆盖整个路径，误走"已存在"分支）——改为仅纯目录名检查

**验证**：`loyan plugin install Vway-yw/loyan-config`（商店渠道）→ remove → 再 install 闭环通过；机器人运行中安装由 watcher 自动热加载。

## 插件商店配置迁移：store_config.json → config.json

**背景**：用户提出配置分文件过细——插件商店是框架共有资产（不支持每实例覆盖），应并入主配置。

**改动**：
- `settings.schema_conf.json` 新增 `store` 嵌套段（type=object+items，sources/git_mirrors/download_base/stats_url 默认值）——schema 唯一来源
- `config_manager.py`：`register_configs_from_schema` 跳过嵌套段（不注册成平铺 ConfigItem）；新增 `get_store_config`/`save_store_config`（读写 config.json 的 store 段）、`_save_config_file`、`_migrate_legacy_store_config`（首次调用自动并入旧文件并删除）
- `plugin_store.py`：删除自管理的 `_config_path`/`_DEFAULT_CONFIG`/读写 merge 逻辑（瘦身约 40 行），改走 config_manager
- `plugin_stats.py`：`stats_url` 不再直读旧文件，改走 config_manager
- 迁移完成：config.json 顶层 6 key（原 5 + store），旧文件已删，面板 GET/PUT `/store/config` 验证读写正常

**约定**（用户定的配置归类规则）：共有单一配置 → config.json；每实例可覆盖 → user_config.json / 实例目录。

## 插件入口规范化（新插件自带问题）

- `storage/plugins/loyan-sticker/`：`StickerPlugin.py` → `main.py`
- `storage/plugins/loyan-game/`：`GamePlugin.py` → `main.py`
- 原因：插件管理器优先找 main.py、fallback {目录名}.py，两者皆无则跳过加载；改名后 watcher 热重载成功（日志"插件 xxx 重载完成"）
- 提醒：上架插件需遵守入口规范（main.py 或 {插件名}.py），否则安装成功也无法加载
