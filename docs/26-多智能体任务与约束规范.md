# 26-多智能体任务与约束规范（插件商店开发）

> 本文件定义插件商店开发中每个智能体的任务、全局约束、核对清单。
> 每个智能体完成后必须对照本文件逐条核对，确认达标才能合并。

## 一、全局约束（所有智能体强制）

1. 日志占比不得超过修改文件的 10%
2. 注释不得超过全文内容的 10%
3. 禁止 emoji（日志、注释、代码全部禁止）
4. 日志格式不单一：允许 error/info/debug 等不同级别
5. 生命周期内涉及底层的、严谨的内容：日志用英语优先（原有日志不管）
6. 严重错误用 raise 向上抛出，不在中层吞异常
7. 插件依赖缺失（requirements 安装失败）不处理，跳过即可
8. 不插手本任务范围外的内容；如遇底层错误，允许修复后并在测试通过后再处理
9. 所有新增代码保持现有文件风格（10 层导入顺序、`# ──` 分节注释风格）
10. 统计服务地址：http://38.55.145.10:16385（HTTP 非 HTTPS）
11. 修改文件前先 Read 完整文件，不凭记忆修改

## 二、智能体 A：plugin_manager 升级

### 任务
- `loyan/core/plugin_manager.py` 新增：
  1. `list_plugins()`：返回已装插件列表 [{name, version, enabled, source, path}]
  2. `enable_plugin(name)`：从禁用集合移除 + 重载
  3. `disable_plugin(name)`：写入禁用集合
  4. `_purge_plugin_modules(name)`：清 sys.modules 中 `loyan.plugins.{name}.*` 前缀
  5. `reload_plugin(name)` 增强：purge + DECORATOR_COMMAND_REGISTRY 按插件名清理 + 支持新装（不在 registry 但目录存在时全量重扫）
  6. `start_watcher()` / `stop_watcher()`：watchfiles 监听 storage/plugins/ + loyan/plugins/，事件 300ms 防抖 -> 定向 reload 或全量重扫
  7. watchfiles 加入 requirements.txt

### 约束
- 不改任何现有公开 API 名称/签名
- 不破坏现有 init/load_disabled_plugins/save_disabled_plugins 逻辑
- watcher 挂 lifecycle READY/SHUTDOWN 钩子（在调用方或本模块内均可，需说明）

### 核对清单
- [ ] list_plugins 返回字段完整
- [ ] enable/disable 与禁用集合文件（.loyan_disabled.json）一致
- [ ] purge 前缀正确（含子模块）
- [ ] reload 新装场景可加载新目录插件
- [ ] watcher 防抖生效、可停止
- [ ] 现有测试不破坏

## 三、智能体 B：plugin_store 源服务

### 任务
- 新建 `loyan/core/plugin_store.py`：
  1. 配置读写：storage/config/store_config.json（sources 数组 + git_mirrors + stats_url，默认 http://38.55.145.10:16385）
  2. 拉取 + 缓存：httpx 拉取各源 store.json，缓存 storage/cache/store.json + updated_at 条件刷新，失败回落缓存
  3. 聚合 `store_list()`：多源合并（同名去重取版本高者、标注源名）+ 本地状态（installed/local_version/update_available/enabled，从 plugin_manager 读）+ 点赞合并（plugin_stats）
  4. 安装 `store_install(id)`：codeload 下载 zip（https://codeload.github.com/{repo}/zip/refs/heads/{branch}）-> 镜像链重试 -> 解压（拒绝 ../ 路径穿越、目录名 = id）-> 移入 storage/plugins/{id} -> reload_plugin
  5. 更新 `store_update(id)`：备份到 storage/backups/plugins/{id}/ -> 替换 -> reload -> 失败恢复备份回滚 -> 成功删备份

### 约束
- 单向依赖 plugin_manager（调 reload_plugin 等），plugin_manager 不反向依赖本模块
- httpx 异步，不用 requests
- 下载/解压全部异步或线程池，不阻塞事件循环

### 核对清单
- [ ] store_config.json 读写正确，默认值含 stats_url
- [ ] 缓存条件刷新 + 失败回落缓存
- [ ] 聚合字段完整（含 update_available 版本对比）
- [ ] 解压拒绝路径穿越（恶意 zip 测试）
- [ ] 更新失败回滚后插件可恢复加载
- [ ] 单向依赖无反向 import

## 四、智能体 C：plugin_stats 统计服务

### 任务
- 新建 `loyan/core/plugin_stats.py`：
  1. `store_like(id)`：POST {stats_url}/likes/{id}（httpx 超时 3s），本地 storage/data/plugin_likes.json 记已点状态防重复，上传失败本地仍记
  2. `get_likes(ids)`：远端 GET {stats_url}/likes 成功用远端；失败降级 seed 稳定随机（md5(id) % 1001，0-1000，刷新不变）；合并本地已点状态
  3. `record_download(id)`：POST {stats_url}/downloads/{id}（下载数上报，失败静默）
  4. 接口标记 stats_ok（远端可用与否）

### 约束
- 纯本地读写 + httpx 远端，不依赖 plugin_manager
- 远端失败不 raise（降级），本地读写失败可 raise
- 文件读写线程安全（加锁）

### 核对清单
- [ ] 点赞防重复（本地已点）
- [ ] 降级随机稳定（同 id 多次调用同值）
- [ ] 远端失败不影响商店主流程
- [ ] 文件读写并发安全
