# 24-事件体系设计（三层模型 + 71 事件类型 + 生产级总线）

> 状态：设计定稿，待实施。事件是框架神经系统——平台推什么框架就能感知什么，插件按事件订阅，生产者与消费者零依赖。

## 一、三层事件模型

| 层 | 事件类 | 定义位置 | 路由 | 频率 |
|---|---|---|---|---|
| 消息事件 | LoyanEvent | loyan_adapter/event.py（已有，不动） | 按 source tag 精准路由到 Runtime | 每条消息 |
| **业务事件** | **BusinessEvent** | **event/types.py（新增，本次核心）** | 按 type 全广播 | 平台通知/系统事件 |
| 生命周期 | LifecycleEvent | lifecycle/hooks/events.py（已有，不动） | 按阶段顺序 | 启动/关闭一次 |

三层不合并：路由策略不同（精准路由 vs 全广播 vs 顺序执行），合并会让总线逻辑互相打架。

## 二、BusinessEvent

```python
@dataclass
class BusinessEvent:
    type: EventType          # 71 个枚举之一
    payload: Any             # 对应事件类型的 Payload dataclass（类型安全）
    source: str = ""         # 来源（"onebot"/"instance_manager"/"brain"）
    adapter_tag: str = ""    # 具体实例 tag（多实例区分）
    timestamp: float = 0.0   # 平台事件时间
    cancelled: bool = False  # 订阅者可拦截（如拒绝好友申请）

    def cancel(self) -> None: self.cancelled = True
```

## 五、EventBus 增强（bus.py）

| 能力 | 说明 |
|---|---|
| publish_business | 全广播、并行、错误隔离、超时保护 |
| 通配订阅 `biz:*` | 订阅所有业务事件（监控/审计） |
| 中间件链 | before/after 拦截：全局过滤/权限/脱敏 |
| 节流/去重 | 高频事件限流 |
| 环形缓冲 | 最近 500 条事件可查（调试/面板） |
| 事件追踪 trace_id | 一条事件贯穿全链路 |
| 事件重试 | 订阅者失败可重试 N 次 |

**健康统计不重造**：复用 lifecycle 的 MetricsCollector（已有 record_hook/hook_summary/latency_p95），EventBus 只调 `lifecycle.metrics.record_hook(f"event:{type}", duration, success)`。

## 六、平台转换器（锁接口，不锁文件）

**框架只锁 `{platform}/adapter.py`**（唯一入口，须能拿到 `create_adapter`），其他文件自由。
事件转换遵循同一模式：**基类可选方法 `parse_business_event`（默认 None）**，实现位置各平台自定。

```python
# loyan/core/loyan_adapter/adapter.py（基类新增可选方法）
class LoyanAdapter(ABC):
    def parse_business_event(self, raw: dict) -> Optional[BusinessEvent]:
        """平台事件 → BusinessEvent；不认识/不支持返回 None

        可选实现：不实现则业务事件被忽略（默认行为）。
        实现位置不限：adapter.py 内联或拆 business.py re-export。
        """
        return None
```

```python
# 框架分发处（适配器收到非消息事件，原来是 return None 丢弃）
business = adapter.parse_business_event(raw)
if business is not None:
    await event_bus.publish_business(business)
```

各平台实现参考行数：onebot ~250（notice 全量）、satori ~180、qq_official ~200、telegram ~170。

## 十一、明确不做

- 不统一三层为一个总线（路由策略不同）
- 不事件持久化/重放（单进程用不上）
- 不跨进程事件（多进程部署时传输层换 Redis，接口不变）
- 不重造健康统计（复用 MetricsCollector）
