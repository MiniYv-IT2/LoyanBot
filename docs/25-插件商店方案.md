# 25-插件商店方案（插件管理升级 + 后端接口 + 商店对接）

> 状态：定稿待实施。基于 GitHub 静态 JSON 源 + 官方统计服务，无服务器方案。
> 统计服务地址（测试）：http://38.55.145.10:16385（美国云服务器，HTTP 非 HTTPS）

## 一、目标

插件管理器升级（热重载/生命周期 API）+ 后端接口 + 插件商店对接一条龙。
商店逻辑归插件域：全部业务逻辑在 `loyan/core/plugin_manager.py`，源服务独立 `plugin_store.py`，统计服务独立 `plugin_stats.py`。

## 二、分层职责

```
webserv/panel/api/{plugins,store}/   HTTP 薄层（参数解析/响应包装）
plugin_manager.py                    插件生命周期 + 热重载 + 安装/更新（业务核心）
plugin_store.py                      源服务（配置/拉取/缓存/聚合/压缩包安装/更新回滚）
plugin_stats.py                      统计服务（点赞上传/降级/本地已点）
storage/                             全部数据落盘
```

## 三、数据流

```
多源 store.json（官方/第三方，GitHub 静态）
  ↓ httpx 拉取 + storage/cache/store.json 缓存（updated_at 条件刷新，失败回落缓存）
聚合（多源合并 + 本地状态 + 版本对比 + 点赞合并）
  ↓
前端 Store 页（搜索/分类/卡片/详情/点赞/安装/更新）
  ↓
下载压缩包（GitHub codeload）→ 解压 → 校验 → storage/plugins/{id}
  ↓ watchfiles 检测目录变化 → 自动热重载
机器人立即生效
```

## 四、JSON 源格式

```json
{
  "store_name": "LoyanBot 插件商店",
  "schema_version": 1,
  "plugins": [
    {
      "id": "Music_Plugin",
      "name": "音乐插件",
      "version": "1.2.0",
      "author": "作者名",
      "icon": "https://.../icon.png",
      "description": "简洁简介（50 字内）",
      "category": "Entertainment",
      "tags": ["音乐", "点歌"],
      "repo": "MiniYv-IT2/Music_Plugin",
      "branch": "main",
      "docs_url": "https://github.com/MiniYv-IT2/Music_Plugin",
      "min_framework": "0.1.0",
      "updated_at": "2026-08-01"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | 唯一 ID = 安装目录名 |
| name/version/author/description | 是 | 展示信息 |
| icon | 否 | 缺省前端 fallback（首字母/默认 logo）|
| category | 是 | 主分类（单选，英文 key：Entertainment/Tools/Manage/Media/Ai/News/Life/Dev/Other，前端 i18n 显示）|
| tags | 是 | 自由标签（多选）|
| repo | 是 | GitHub owner/repo，下载源 |
| branch | 否 | 默认 main |
| docs_url | 否 | 查看文档外链 |
| min_framework | 否 | 框架版本下限检查 |
| updated_at | 否 | 更新时间 |

## 六、plugin_manager.py 新增（插件生命周期）

1. 插件管理公开方法：
   - `list_plugins()` -> [{name, version, enabled, source, path}]
   - `enable_plugin(name)`：从禁用集合移除 + 重载
   - `disable_plugin(name)`：写入禁用集合（复用 load/save_disabled_plugins）
2. 重载增强 `reload_plugin(name)`：
   - `_purge_plugin_modules(name)`：清 sys.modules 的 `loyan.plugins.{name}.*` 前缀
   - DECORATOR_COMMAND_REGISTRY 按插件名清理（防重复注册）
   - 支持新装：插件不在 registry 但目录存在 -> 全量重扫
3. watchfiles 热重载：
   - `start_watcher()` / `stop_watcher()`：监听 storage/plugins/ + loyan/plugins/
   - 事件（added/modified/deleted）-> 300ms 防抖 -> 定向 reload 或全量重扫
   - 挂 lifecycle READY/SHUTDOWN 钩子
   - watchfiles 加入 requirements.txt

## 七、plugin_store.py（源服务）

1. 配置（storage/config/store_config.json）：
   ```json
   {
     "sources": [
       {"name": "官方", "store_url": "http://38.55.145.10:16385/store.json", "enabled": true}
     ],
     "git_mirrors": ["https://ghproxy.com/"],
     "stats_url": "http://38.55.145.10:16385/likes"
   }
   ```
2. 拉取 + 缓存：httpx 拉取各源 store.json，缓存 storage/cache/store.json + updated_at 条件刷新，失败回落缓存（stale-while-error）
3. 聚合 `store_list()`：多源合并（同名去重取版本高者、标注源名）+ 本地状态（installed/local_version/update_available/enabled）+ 点赞合并（plugin_stats）
4. 安装 `store_install(id)`（压缩包模式）：
   - 下载 URL：`https://codeload.github.com/{repo}/zip/refs/heads/{branch}`
   - 镜像链重试：直连 -> mirror 前缀 -> 全失败报错
   - httpx 下载 -> 临时文件 -> zipfile 解压到临时目录（拒绝路径穿越 `../`、校验解压后目录名 = id）-> 移动到 storage/plugins/{id} -> reload_plugin(id)
5. 更新 + 回滚 `store_update(id)`：
   - 备份当前目录到 storage/backups/plugins/{id}/
   - 下载新压缩包 -> 解压 -> 替换 storage/plugins/{id}
   - reload_plugin(id)
   - 任一失败（下载/解压/reload 失败）：删新目录 -> 恢复备份 -> reload_plugin(id) 回旧版
   - 回滚后仍失败：保留现场 + 报错
   - 成功：删备份

## 八、plugin_stats.py（统计服务）

1. 点赞上传 `store_like(id)`：
   - POST {stats_url}/likes/{id}（httpx，超时 3s）
   - 本地 storage/data/plugin_likes.json 记 {id: 1}（已点状态，防重复）
   - 上传失败：本地仍记，恢复后补传
2. 读取 `get_likes(ids)`：
   - 远端 GET {stats_url}/likes 成功 -> 用远端
   - 失败 -> 降级：seed 稳定随机（md5(id) % 1001，0-1000，刷新不变）
   - 合并本地已点状态
3. 统计服务挂了不影响商店：仅 likes 显示降级，接口标记 stats_ok

## 十二、开发约束（全局强制）

1. 日志占比不得超过修改文件的 10%
2. 注释不得超过全文内容的 10%
3. 禁止 emoji（日志、注释、代码全禁）
4. 日志格式不单一：允许 error/info/debug 等级别
5. 生命周期内涉及底层的、严谨的内容：日志用英语优先（原有日志不管）
6. 严重错误用 raise 向上抛出，不在中层吞异常
7. 插件依赖缺失（requirements 安装失败）不处理，跳过即可
8. 不插手本任务范围外的内容；如遇底层错误，允许修复后在测试通过后再处理
9. graci 是 API 透传层，有需要可加内容，方便后续对接和暴露
