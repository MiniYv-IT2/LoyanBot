## 一、背景与目标

现状问题：

1. 面板刷新/关闭页面导致流式中断，AI 生成无法继续
2. `/chat` 命令裸用 `ctx.sender_id` 当 session_id，群聊多人共用记忆，私聊跨实例串记忆
3. `IdentityTag.instance_id` 每次随机生成（重连/改名/重载都变），无法作为稳定标识
4. `core/loyan_session/` 的 LoyanSessionManager 是死代码，从未被真正消费

目标：

- 面板：关闭页面后 AI 继续生成，重开页面可恢复查看
- 统一且分离的会话 ID 机制（面板与会话层互不干扰）
- instance_id 持久化，重启/改名/重载保持不变
- 会话管理器真正发挥作用（插件与内置命令统一走会话层）
- 群聊默认公共记忆

## 三、会话 ID 方案

### 面板会话 ID（Panel）

```
chat_panel_web_{YYYYMMDDHHMMSS}_{8位小写字母数字}
例：chat_panel_web_20260806170823_ab3x9kq2
```

- 由面板 API 创建会话时生成，与 IM 会话完全隔离
- 存储于现有 `sessions` / `messages` 表（chat_sessions 库）

### IM 会话 ID（机器人侧）

```
chat_{platform}_{instance_id}_{chat_type}_{peer_id}[_{sub_id}]
例：chat_qq_official_3d03a9f1_private_123456
    chat_qq_official_3d03a9f1_group_987654          （群聊公共记忆，默认）
    chat_qq_official_3d03a9f1_group_987654_556677   （群聊个人子记忆，可选）
```

- `platform`：适配器协议（onebot / qq_official / telegram ...）
- `instance_id`：实例持久化标识（Part A），改名/重载不变
- `chat_type`：private / group
- `peer_id`：对端 ID（私聊=用户，群聊=群号）
- `sub_id`：可选段；群聊默认**公共记忆**不带 sub_id；开启个人子记忆时追加 sender_id
- 存储于新表 `im_sessions` / `im_messages`（chat_sessions 库，与面板分表隔离）

## 四、Part A：instance_id 持久化

目标：instance_id 一经生成即固定，重启/改名/热重载不变化。

做法：

1. `IdentityTag` 增加从外部注入 instance_id 的能力（构造参数可选）
2. 实例 config 文件 `storage/instances/{bot_name}/config.json` 自动填充 `instance_id` 字段：
   - 启动发现实例时，若 config 无 `instance_id` → 生成并写回 config（机器行为）
   - 已有则直接使用，不再每次随机
3. `_build_runtime` / `_create_and_prepare_adapter` / `_register_instance` 读取 config 的 `instance_id` 传入 IdentityTag
4. 面板表单**不渲染** `instance_id` 字段（用户无感知；表单 schema 排除该 key）
5. 改名/重载时 `instance_id` 从 config 读取，保持不变

## 五、Part B：统一会话层

目标：让 `core/loyan_session/` 真正发挥作用，所有 IM 对话统一走会话层。

新增 `core/loyan_session/resolve.py`：

- `resolve_im_session_id(platform, instance_id, chat_type, peer_id, sub_id=None) -> str`
  按第三节格式生成 IM 会话 ID（群聊默认公共记忆：不带 sub_id）
- `resolve_from_context(ctx) -> str`：从 PluginContext 提取 platform/instance_id/chat_type/peer_id
  （`ctx.runtime.adapter_tag`、`ctx.chat_type`、`ctx.sender_id` / `ctx.target_id`）

改造：

1. `brain/commands/chat.py`：
   - `handle_chat` 用 `resolve_im_session_id(...)` 替换裸 `ctx.sender_id`
   - `handle_chat_reset` 改为真正重置会话（走 loyan_session_manager，清 im_messages）
2. `loyan_session_manager` 激活：
   - 会话创建/获取/销毁/清理/上下文读写全部真正被调用
   - `_generate_session_id` 对齐新格式（或由 resolve.py 提供，manager 复用）
3. 记忆存储分表：
   - 新建 `im_sessions`（id, name, created, updated）与 `im_messages`（id, session_id, role, content, reasoning, duration, created）
   - IM 对话读写走 `im_messages`；面板仍走 `messages`，互不干扰
4. 群聊默认公共记忆：`shared_group_session` 默认 True（IM 侧）
5. 插件可通过 `from loyan.core.loyan_session import ...` 使用会话能力（保持现有便捷函数 API 不变，实现改为真正落库）

## 六、Part C：后台任务化

目标：面板发起生成后，即使关闭页面任务继续；重开页面可恢复。

新增 `core/loyan_session/task/`：

- `task/chat_task.py`：ChatTask 数据类（task_id, session_id, status, events, created, done）
- `task/manager.py`：TaskManager（单例）——创建/查询/取消任务、事件队列、运行中任务恢复
- `task/__init__.py`：导出

改造 `panel/api/chat/__init__.py`：

1. 新增 `POST /api/loyanui/chat/tasks`：创建后台任务，立即返回 `{task_id}`（不阻塞）
2. 新增 `GET /api/loyanui/chat/tasks/<task_id>/events`：SSE 订阅任务事件流（可断线重连）
3. 新增 `GET /api/loyanui/chat/tasks`：列出运行中/最近任务（重开页面恢复用）
4. 新增 `POST /api/loyanui/chat/tasks/<task_id>/cancel`：取消任务
5. 原 `POST /api/loyanui/chat/stream` 保留兼容（内部改为创建任务 + 立即订阅，前端无需大改）
6. 任务事件：`{type: text|reasoning|done|error, ...}`；任务完成时自动落库 im_messages / messages + 自动标题

前端（panel/src/pages/Dashboard/Chat/index.jsx）最小适配：

- 发送消息改走 tasks 接口，持有 task_id
- 断线（页面刷新/关闭）后重开：查询运行中任务，重新订阅 events 续收
- 取消按钮调用 cancel 接口
