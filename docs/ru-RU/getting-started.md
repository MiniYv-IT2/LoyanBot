# Быстрый старт

LoyanBot - это легкий, асинхронный, кроссплатформенный фреймворк чат-ботов, построенный на Python 3.11+. Он подключается к платформам QQ (через NapCat/OneBot), QQ Official, Telegram и Satori, а также интегрируется с поставщиками LLM, включая OpenAI, Anthropic, Ollama и LiteLLM.

## 1. Требования

### Версия Python

- Требуется Python 3.11 или выше (поддерживаются 3.12 и 3.13)

### Системные зависимости

- Операционная система: Linux, macOS или Windows
- Менеджер пакетов `pip` (входит в Python)
- Для развертывания в Docker: Docker Engine 20.10+ и Docker Compose v2

### Основные зависимости

Следующие пакеты устанавливаются автоматически через pip:

| Пакет | Назначение |
|-------|------------|
| quart | Асинхронный веб-фреймворк для панели и HTTP-коллбэков |
| hypercorn | ASGI-сервер для Quart |
| aiohttp | Асинхронный HTTP-клиент/сервер |
| websockets | Поддержка WebSocket для OneBot WS-режима |
| openai | Клиент OpenAI API |
| litellm | Универсальный шлюз поставщиков LLM |
| Pillow | Генерация изображений (карточки помощи и т.д.) |
| psutil | Мониторинг системы |
| aiosqlite | Асинхронный доступ к SQLite |
| watchfiles | Наблюдение за файлами для горячей перезагрузки плагинов |
| python-telegram-bot | Адаптер Telegram |
| pycryptodome | Криптографические операции |

### Опциональные зависимости

- `playwright` (для поиска на основе браузера)
- `mss` и `py-cpuinfo` (для расширенного мониторинга системы)

## 2. Установка

### Установка через pip (рекомендуется)

```bash
# Установка из PyPI
pip install loyan

# Установка со всеми опциональными зависимостями
pip install loyan[all]
```

### Установка из исходников

```bash
# Клонирование репозитория
git clone https://github.com/MiniYv-IT2/LoyanBot.git
cd LoyanBot

# Установка в режиме разработки
pip install -e .

# Установка со всеми опциональными зависимостями
pip install -e ".[all]"
```

### Установка через Docker

```bash
# Клонирование репозитория
git clone https://github.com/MiniYv-IT2/LoyanBot.git
cd LoyanBot

# Сборка и запуск через Docker Compose
docker compose -f docker/docker-compose.yml up -d

# Ручная сборка образа
docker build -f docker/Dockerfile -t loyan:latest .
docker run -d -p 5090:5090 -v loyan_storage:/loyan/storage --name loyan loyan:latest
```

Docker-тома:
- `/loyan/storage` - Постоянная конфигурация, экземпляры, логи и данные плагинов
- `/loyan/plugins_custom` - Опциональный каталог пользовательских плагинов

Панель доступна на порту **5090**.

## 3. Конфигурация

### Расположение файла конфигурации

После первого запуска файл конфигурации находится по адресу:

```
<корень_проекта>/storage/config.json
```

### Базовая структура конфигурации

Файл конфигурации фреймворка (`config.json`) содержит глобальные настройки:

```json
{
  "callback_port": 3002,
  "connection_mode": "http",
  "bot_version": "v1.9.25",
  "log_encoding": "utf-8",
  "log_level": "INFO",
  "debug_mode": false,
  "auto_replies": {
    "привет": "Привет! Я LoyanBot, чем могу помочь?"
  },
  "store": {
    "sources": [
      {
        "name": "Официальный",
        "store_url": "http://38.55.145.10:16385/store.json",
        "enabled": true
      }
    ]
  }
}
```

### Основные поля конфигурации

| Поле | Тип | Значение по умолчанию | Описание |
|------|-----|----------------------|----------|
| `log_level` | string | `"INFO"` | Уровень логирования: DEBUG, INFO, WARNING, ERROR, CRITICAL |
| `debug_mode` | bool | `false` | Включение отладочного режима (структурированное логирование) |
| `log_encoding` | string | `"utf-8"` | Кодировка файлов логов |
| `auto_replies` | dict | `{}` | Соответствие ключевых слов автоматическим ответам |
| `auto_update` | bool | `true` | Ежедневное автоматическое обновление плагинов |
| `auto_update_core` | bool | `false` | Автоматическая проверка обновлений фреймворка |

### Переменные окружения

Значения конфигурации можно переопределять через переменные окружения:

| Переменная окружения | Ключ конфигурации | Описание |
|---------------------|-------------------|----------|
| `GRACYBOT_HOME` | - | Переопределение корневой директории проекта |

## 4. Конфигурация экземпляров

LoyanBot поддерживает несколько экземпляров ботов. Конфигурация каждого экземпляра находится по адресу:

```
storage/instances/<имя_экземпляра>/config.json
```

### Пример конфигурации экземпляра

```json
{
  "platform": "onebot",
  "bot_name": "ОсновнойБот",
  "robot_id": "123456789",
  "master_id": "987654321",
  "enabled": true,
  "type": "http",
  "http_url": "http://127.0.0.1:3000",
  "callback_port": 3002
}
```

### Поля конфигурации экземпляра

| Поле | Тип | Обязательно | Описание |
|------|-----|-------------|----------|
| `platform` | string | Да | Тип платформы: `onebot`, `qq_official`, `telegram`, `satori` |
| `bot_name` | string | Да | Пользовательское имя для логирования и идентификации |
| `robot_id` | string | Да | ID аккаунта бота (номер QQ, токен Telegram и т.д.) |
| `master_id` | string | Да | ID владельца для команд администратора |
| `enabled` | bool | Нет | Включен ли этот экземпляр (по умолчанию: true) |
| `type` | string | Нет | Тип подключения для OneBot: `http`, `ws_forward`, `ws_reverse` |
| `http_url` | string | Нет | URL HTTP API |
| `callback_port` | int | Нет | Порт для получения HTTP-коллбэков |
| `admins_id` | list | Нет | Дополнительные ID администраторов |

### Создание экземпляра

Используйте CLI для создания нового экземпляра бота:

```bash
loyan instance add <имя_экземпляра>
```

Это создаст директорию `storage/instances/<имя_экземпляра>/` с файлом `config.json` по умолчанию.

## 5. Запуск

### CLI команда

```bash
loyan run
```

### Прямое выполнение Python

```bash
python bot.py
```

### Docker

```bash
docker compose -f docker/docker-compose.yml up -d
```

### Последовательность запуска

Бот следует фазированной последовательности запуска:

1. **Загрузка конфигурации** - Чтение `config.json` и конфигураций экземпляров
2. **Готовность базы данных** - Инициализация подключений к базе данных
3. **Сканирование плагинов** - Сканирование каталогов плагинов и чтение метаданных
4. **Загрузка плагинов** - Загрузка модулей плагинов и регистрация команд
5. **Готовность Brain** - Инициализация AI-поставщиков и хранилища ключей
6. **Готовность экземпляров** - Создание экземпляров ботов с Pipeline
7. **Готовность адаптеров** - Подключение к платформам обмена сообщениями
8. **Работает** - Полностью готов к приему сообщений

### Вывод при запуске

При успешном запуске бота вы увидите:

```
====== LoyanBot v{версия} ======
```

А владелец получит приветственное сообщение в личных сообщениях:

```
LoyanBot v{версия} успешно запущен!
Загружено {N} плагинов
```

## 6. Проверка установки

### Проверка статуса бота

После запуска отправьте команду `/about` боту в личных сообщениях. Он ответит:

```
LoyanBot v{версия}
- Автор: MiniYv
- Позиция: Кроссплатформенный легкий асинхронный IM-фреймворк
- Адаптеры: onebot/ОсновнойБот (HTTP)
- Python: 3.11.x
- Плагины: N зарегистрировано
```

### Проверка команд плагинов

Отправьте `/help` боту. Он сгенерирует изображение справки со всеми зарегистрированными командами плагинов.

### Проверка логов

Логи хранятся по адресу:

```
storage/logs/loyan.log        # Все логи (DEBUG и выше)
storage/logs/loyan_error.log  # Только логи ошибок
```

### Проверка веб-панели

Если настроен `http_port`, веб-панель доступна по адресу:

```
http://localhost:5090
```

## 7. Часто задаваемые вопросы

### "Файл конфигурации не найден"

Бот автоматически создает конфигурацию по умолчанию при первом запуске. Если появляется это сообщение, проверьте, доступна ли директория `storage/` для записи.

### "Нет запущенных адаптеров"

Убедитесь, что в `storage/instances/` существует хотя бы одна конфигурация экземпляра с `enabled: true` и допустимым типом платформы.

### "Плагин X: отсутствует metadata.toml"

Каждая директория плагина должна содержать файл `metadata.toml`. Проверьте структуру директории плагина.

### Отказ подключения к HTTP-коллбэку

Если используется HTTP-режим, убедитесь, что NapCat или реализация OneBot запущена, и `callback_port` в конфигурации экземпляра соответствует конфигурации коллбэка NapCat.

### Docker: "В доступе отказано"

Контейнер Docker по умолчанию работает от root. Если монтируете тома из каталога хоста, убедитесь в правильных правах:

```bash
chmod -R 777 storage/
```

### Горячая перезагрузка плагинов не работает

Убедитесь, что установлен `watchfiles`:

```bash
pip install watchfiles
```

### Логи слишком подробные

Установите `log_level` в `WARNING` в `config.json`:

```json
{
  "log_level": "WARNING"
}
```
